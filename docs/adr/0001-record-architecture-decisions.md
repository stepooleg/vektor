# ADR 0001. Ведение архитектурных решений (ADR)

- **Дата:** 2026-08-06
- **Статус:** Принято

## Контекст

Проект Vektor — крупное корпоративное HR-приложение с длительным жизненным циклом,
несколькими модулями (оценка, LMS, ИПР, аналитика) и требованиями безопасности (152-ФЗ).
Важно фиксировать ключевые проектные решения с их обоснованием, чтобы новые участники
(включая агентов) понимали контекст и не пересматривали закрытые вопросы.

## Решение

Вести архитектурные решения в каталоге `docs/adr/` в формате ADR
(Architecture Decision Record), по одному файлу на решение:

- Шаблон имени: `NNNN-короткий-слаг.md`, нумерация сквозная.
- Структура: **Контекст → Решение → Последствия → Альтернативы**.
- Статусы: `Принято` / `Устарело` / `Заменено на ADR-NNNN`.
- ADR дополняют (не заменяют) `SPEC.md` и `AGENTS.md`.

## Последствия

- Каждое значимое решение (стек, структура, интеграции, безопасность) оформляется ADR.
- Изменение ранее принятого решения — новый ADR со ссылкой и сменой статуса старого.
- Новые участники могут быстро войти в контекст.
