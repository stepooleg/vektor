# Спецификация HR-приложения «Vektor»

**Версия:** 1.1
**Дата:** 2026-08-08
**Статус:** Уточнённая редакция (MBO/OKR добавлены, мультиязычность/моб. отклонены)
**Источник:** Интервью с заказчиком

---

## 1. Назначение и обзор продукта

### 1.1. Цель продукта
Создать корпоративное HR-приложение, которое позволит:
1. Собирать обратную связь о сотрудниках (в т.ч. по методологии 360°);
2. Проводить периодическую оценку персонала (360°, самооценка, матрица компетенций);
3. Автоматически формировать и сопровождать индивидуальные планы развития (ИПР);
4. Создавать и проходить обучающие курсы во встроенном LMS;
5. Вести непрерывную обратную связь и портфолио достижений сотрудников;
6. Предоставлять руководству и HR аналитику по компании, подразделениям, сотрудникам и обучению.

### 1.2. Краткое резюме требований (из интервью)

| Параметр | Решение |
|---|---|
| Размер организации | 100–500 пользователей |
| Интеграция с кадрами | 1С:ЗУП (односторонняя, оргструктура) |
| Платформа | Web + PWA |
| Развёртывание | On-premise (сервер внутри периметра организации) |
| Роли | HR-администратор, Руководитель, Сотрудник, Методолог/Куратор |
| Виды оценки | 360° + Самооценка + Матрица компетенций |
| Периодичность | 1–2 раза в год (+ ручной запуск цикла) |
| Анонимность ОС | Полная |
| Обучение | Встроенный LMS (тексты, тесты, задания с проверкой) |
| ИПР | Автоподбор из результатов оценки + ручная правка |
| Сертификация | Только статус «пройдён / не пройдён» |
| Авторизация | SSO (AD/LDAP) + запасной вход по паролю |
| Уведомления | Email + Push (PWA) |
| Язык интерфейса | Только русский |
| Напоминания | Авто + эскалация при просрочке |
| Безопасность | 152-ФЗ/УЗ, RBAC, резервные копии |
| Компетенции | Конструктор + готовые шаблоны |
| Непрерывная ОС | Да + журнал достижений (портфолио) |
| Дашборды | По компании, по сотруднику, по подразделениям, по обучению |
| Подход к запуску | Не ограничен по срокам — приоритет функциональности и качества |
| Стек | На усмотрение исполнителя (см. рекомендацию в §11) |

## 2. Роли и права доступа (RBAC)

### 2.1. Ролевая модель

| Роль | Описание | Ключевые права |
|---|---|---|
| **HR-администратор** | Владелец процессов оценки и развития в компании | Полный доступ: настройка циклов, шаблонов, компетенций; просмотр всей агрегированной аналитики; управление пользователями и ролями; доступ к обезличенным сырым данным оценок |
| **Руководитель** | Менеджер отдела/команды | Управление циклами оценки своей команды; просмотр результатов подчинённых (агрегированно); формирование/утверждение ИПР подчинённых; доступ к дашбордам подразделения |
| **Сотрудник** | Любой работник компании | Проходит оценку (как оцениваемый и как оценщик); даёт отзывы; самооценка; прохождение курсов; просмотр своего ИПР и портфолио |
| **Методолог / Куратор** | Специалист по обучению/методологии | Создание и редактирование курсов, учебных материалов, шаблонов опросов и моделей компетенций; проверка практических заданий |

### 2.2. Принципы доступа
- Доступ реализован по **ролевой модели (RBAC)** с гранулярными правами на действия и объекты.
- **Принцип минимума привилегий:** руководитель видит данные только своих подчинённых.
- **HR** имеет доступ к **агрегированным** результатам оценок; сырые ответы отдельных оценщиков при анонимных циклах **недоступны** (см. §6.3).
- Возможны **составные роли** (например, руководитель + куратор).
- Все действия над чувствительными данными журналируются (audit log).

## 3. Организационная структура и пользователи

### 3.1. Источник данных
- Организационная структура (сотрудники, должности, отделы, иерархия руководителей) **синхронизируется из 1С:ЗУП** в **одностороннем** порядке (из 1С → в приложение).
- Синхронизация по расписанию (рекомендуется: 1 раз в сутки ночью + возможность ручного запуска).

### 3.2. Состав синхронизируемых данных
- Подразделения (дерево отделов);
- Должности/штатные единицы;
- Сотрудники: ФИО, табельный номер, должность, подразделение, руководитель, дата приёма;
- Связь «руководитель — подчинённый» (для оценки 360°).

### 3.3. Дополнительные данные в приложении (не из 1С)
- Учётные данные для входа (привязка к AD/LDAP или локальный пароль);
- Контактные данные для уведомлений (email берётся из AD или задаётся вручную);
- Фото профиля (загружается пользователем или из AD);
- Портфолио, ИПР, история оценок и обучения.

### 3.4. Обработка кадровых изменений
- Увольнение сотрудника → архивирование профиля, сохранение истории.
- Перевод в другой отдел → корректный перенос истории с указанием даты.
- Декрет/отпуск → возможность поставить статус «не участвует в оценке» на период.

## 4. Модуль «Модель компетенций»

### 4.1. Конструктор компетенций
- HR / Методолог может создавать произвольную **модель компетенций** (competency framework):
  - Группы компетенций (например, «Лидерство», «Профессиональные», «Корпоративные ценности»);
  - Индивидуальные компетенции с описанием;
  - Шкала оценки (например, 1–5 или 1–10) — настраивается;
  - Поведенческие индикаторы по уровням (для калибровки оценщиков).

### 4.2. Готовые шаблоны
На старте поставляются предустановленные шаблоны:
- **Корпоративные ценности** (универсальный);
- **Лидерство и управление** (для руководителей);
- **Коммуникации и командная работа**;
- **Профессиональная эффективность**.

### 4.3. Привязка компетенций
- Модель компетенций может быть:
  - Корпоративной (общей для всех);
  - Ролевой (для конкретных должностей/грейдов);
  - Индивидуальной (назначенной конкретному сотруднику).

## 5. Модуль «Оценка»

### 5.1. Поддерживаемые виды оценки

#### 5.1.1. Оценка 360°
- Оцениваемого сотрудника оценивают несколько групп:
  - **Руководитель** (обязательно);
  - **Коллеги** (peers, одного уровня);
  - **Подчинённые**.
- *Примечание:* клиенты/смежники в оценке не участвуют (по результатам интервью).
- Состав оценщиков определяется:
  - Автоматически (по оргструктуре: руководитель + все/часть подчинённых/коллег), либо
  - Вручную (HR/руководитель формирует список оценщиков), либо
  - Комбинированно.
- Минимальное количество оценщиков в группе для отображения агрегированного результата (порог анонимности, по умолчанию — не менее 3) настраивается HR, чтобы не деанонимизировать отдельных участников.

#### 5.1.2. Самооценка
- Сотрудник оценивает себя по тем же компетенциям.
- В отчёте сравнивается с оценкой окружения (разрыв self vs others).

#### 5.1.3. Матрица компетенций
- Оценка сотрудника по сетке «компетенция × уровень» с привязкой к грейду/должности.
- Визуальное отображение: «текущий уровень vs ожидаемый для роли».

### 5.2. Жизненный цикл цикла оценки
1. **Создание цикла** (HR): выбор шаблона, состава участников, периода, сроков;
2. **Формирование списков оценщиков** (автоматически / вручную);
3. **Старт цикла**: рассылка уведомлений;
4. **Заполнение оценок** участниками;
5. **Завершение приёма ответов** по дедлайну;
6. **Расчёт агрегированных результатов**;
7. **Формирование отчётов и ИПР**;
8. **Закрытие цикла**, архивирование.

### 5.3. Содержание опросника
- Количественные оценки по компетенциям (по выбранной шкале);
- Качественные открытые комментарии (опционально, по каждой компетенции и/или общие);
- Возможность добавления кастомных вопросов (HR/Методолог).

### 5.4. Напоминания и эскалация
- **Автоматические напоминания** оценщикам:
  - За N дней до дедлайна (по умолчанию 3 дня);
  - В день дедлайна.
- **Эскалация** при просрочке:
  - Уведомление сотруднику (повторно);
  - Уведомление его руководителю;
  - Уведомление HR при критической просрочке (порог настраивается).

## 6. Модуль «Обратная связь и портфолио»

### 6.1. Непрерывная (неформальная) обратная связь
- Помимо формальных циклов, сотрудники могут:
  - Отправить **благодарность / признание** коллеге (публично или приватно);
  - **Запросить обратную связь** у выбранных коллег в любой момент;
  - Оставить отзыв по конкретному проекту/кейсу.

### 6.2. Журнал достижений (портфолио сотрудника)
- Сотрудник и его руководитель могут добавлять:
  - Достижения и результаты;
  - Завершённые проекты и кейсы;
  - Полученные благодарности;
  - Пройденные курсы и сертификаты-статусы.
- Портфолио учитывается при очередной оценке и при формировании ИПР.

### 6.3. Анонимность обратной связи
- **Полная анонимность** для формальных циклов 360°:
  - Сотрудник не видит, кто именно как его оценил;
  - HR/руководитель видят **только агрегированные** результаты по группам («руководитель», «коллеги», «подчинённые»);
  - Действует **пороговое минимальное количество** оценщиков в группе для отображения результата (защита от деанонимизации);
  - Сырые ответы отдельных лиц недоступны никому, кроме системного аудит-лога.
- Для неформальной ОС анонимность настраивается отправителем (анонимно / от своего имени).

## 7. Модуль «Обучение (встроенный LMS)»

### 7.1. Каталог курсов
- Иерархический каталог по категориям;
- Поиск и фильтрация;
- Возможность привязки курса к компетенции (для автоподбора в ИПР);
- Курс может быть обязательным (назначен) или добровольным.

### 7.2. Форматы учебных материалов
Поддерживаемые форматы контента (согласно интервью):
- **Текстовые материалы** (статьи, конспекты) с форматированием и вложениями;
- **Тесты** (автоматическая проверка):
  - Несколько типов вопросов (один/несколько ответов, шкала, текст);
  - Настройка проходного балла, числа попыток, перемешивания вопросов;
  - Автоматическое выставление результата.
- **Практические задания с проверкой куратором**:
  - Сотрудник прикрепляет ответ (текст/файл);
  - Куратор проверяет, оставляет комментарий и оценку («зачёт/незачёт» или по шкале).

### 7.3. Автор курсов
- Курсы создаются ролью **Методолог/Куратор**;
- Редактор курса: структура из уроков/модулей в нужном порядке;
- Возможность черновика, предпросмотра, публикации.

### 7.4. Прогресс и сертификация
- Отслеживание прогресса по каждому курсу (% завершения, статус);
- **Сертификация — только статус** «пройдён / не пройдён» (без PDF-сертификатов на первом этапе);
- Запись пройденных курсов в портфолио сотрудника.

## 8. Модуль «Индивидуальный план развития (ИПР)»

### 8.1. Принцип формирования
- **Автоподбор из результатов оценки**:
  - По итогам цикла 360°/матрицы компетенций система определяет **зоны развития** (компетенции с оценкой ниже ожидаемой);
  - Для каждой зоны предлагаются курсы/материалы из каталога (по привязке к компетенциям);
  - Предлагаются также действия (задания, менторство, проекты).
- **Ручная правка**:
  - HR и/или руководитель корректируют предложенный план;
  - Добавляют/удаляют пункты, меняют сроки;
  - Назначают ответственных (менторов, кураторов).

### 8.2. Структура ИПР
- Цель развития (привязка к компетенции);
- Действия (курс, задание, менторство, чтение, практика);
- Сроки и контрольные точки;
- Ответственный/наставник;
- Статус (запланировано / в работе / завершено / просрочено);
- Связь с журналом достижений.

### 8.3. Жизненный цикл
1. Формирование (авто + правка) после цикла оценки;
2. Согласование с сотрудником;
3. Выполнение с отслеживанием прогресса;
4. Контрольные встречи (отметки в системе);
5. Оценка результатов на следующем цикле.

## 9. Аналитика и дашборды

### 9.1. Дашборд «Общий по компании» (HR, топ-менеджмент)
- Охват оценок: % сотрудников с завершённой оценкой;
- Динамика средних баллов по компании во времени;
- Тепловая карта сильных/слабых компетенций по компании;
- Активность обучения: кол-во проходящих курсы, завершаемость;
- KPI процессов: % просрочек, среднее время прохождения.

### 9.2. Дашборд «По сотруднику» (сотрудник сам + руководитель/HR)
- Профиль компетенций (радар);
- Динамика по циклам оценки;
- Сравнение самооценки vs окружение;
- Прогресс ИПР и обучения;
- Портфолио достижений.

### 9.3. Дашборд «По подразделениям» (руководитель, HR)
- Сравнение отделов по средним оценкам;
- Узкие места по компетенциям команды;
- Ранжирование сотрудников по уровню развития компетенций (с учётом приватности).

### 9.4. Дашборд «По обучению» (HR, Методолог)
- Популярные курсы, средняя завершаемость;
- Успеваемость по тестам, типичные ошибки;
- Эффективность курсов (корреляция «курс → рост компетенции» в следующем цикле).

### 9.5. Экспорт
- Выгрузка отчётов в **PDF** и **Excel**;
- Графики для вставки во внешние презентации.

## 10. Интеграции

### 10.1. 1С:ЗУП
- **Тип:** односторонняя синхронизация оргструктуры (1С → приложение);
- **Способ:** REST/SOAP-API 1С или обмен через файлы (в зависимости от конфигурации);
- **Расписание:** nightly + ручной запуск;
- **Логирование** всех изменений оргструктуры.

### 10.2. Active Directory / LDAP (SSO)
- Вход через корпоративную учётную запись (SAML/OIDC или LDAP bind);
- **Запасной механизм:** локальный логин-пароль (для внешних консультантов или при недоступности AD);
- Синхронизация пользователей из AD опциональна.

### 10.3. Email
- SMTP-сервер организации для отправки уведомлений.

### 10.4. Push (PWA)
- Web Push API через сервис-воркер;
- Подписка на push при первом входе (с согласия пользователя).

## 11. Технические рекомендации

### 11.1. Рекомендуемый стек

| Слой | Технология | Обоснование |
|---|---|---|
| **Backend** | Python 3.12 + **Django 5** + Django REST Framework | Зрелая экосистема, удобство on-premise, отличная работа с реляционными БД и интеграциями (1С, AD), богатые библиотеки. Альтернатива: **FastAPI** при событийной архитектуре. |
| **База данных** | **PostgreSQL 16** | Зрелость, производительность, JSON-поля для гибких опросников, полнотекстовый поиск. |
| **Frontend** | **React 18 + TypeScript** | Большой рынок разработчиков, обилие библиотек для дашбордов (Recharts/Chart.js), форм и таблиц. |
| **UI-кит** | Ant Design / MUI | Готовые компоненты таблиц, форм, графиков под корпоративный стиль. |
| **PWA** | Vite + Service Worker (Workbox) | Офлайн-кеш, push-уведомления, установка на рабочий стол. |
| **Очереди/фон** | **Celery + Redis** | Рассылка уведомлений, напоминания, синхронизация с 1С, расчёт агрегатов. |
| **Контейнеризация** | Docker + Docker Compose | Удобство on-premise установки, изоляция. |
| **Web-сервер** | Nginx + Gunicorn (или Caddy) | Раздача статики, терминация TLS, reverse-proxy. |
| **SSO** | django-saml2 / python3-saml / django-auth-ldap | Готовые решения для AD/LDAP. |

> Альтернатива при наличии у команды .NET-экспертизы: **.NET 8 + ASP.NET Core + Angular** — также полностью подходит для on-premise и Windows-инфраструктуры.

### 11.2. Архитектура
- Монолитное приложение с модульной структурой по доменам (оценка, обучение, ИПР, аналитика, интеграции).
- Разделение на сервисы (background workers) для асинхронных задач.
- API-first: backend предоставляем REST (или GraphQL) API; frontend — отдельный SPA/PWA.

### 11.3. Производительность
- Целевая нагрузка: **до 500 активных пользователей**, пиковая (период оценки) — до 200 одновременных.
- Время отклика UI — не более 2 с для 95% запросов.

## 12. Безопасность и комплаенс

### 12.1. Соответствие 152-ФЗ / УЗ
- Хранение и обработка персональных данных в соответствии с ФЗ-152 «О персональных данных»;
- Назначение ответственного за обработку ПДн;
- Получение согласий на обработку ПДн (если требуется);
- Политики хранения и сроков хранения данных оценок;
- Уведомление Роскомнадзора (при необходимости).

### 12.2. Защита данных
- **Шифрование** данных:
  - At rest: шифрование БД и бэкапов, шифрование дисков;
  - In transit: TLS 1.2+ для всего трафика.
- **Хеширование** паролей (современные алгоритмы: Argon2/bcrypt).
- **Раздельный доступ** по RBAC (см. §2).
- **Маскирование** критичных данных в логах и интерфейсах.

### 12.3. Журналирование (Audit log)
- Кто, когда и какое действие выполнил над чувствительными данными;
- Особое внимание: доступ к результатам оценок, выгрузкам, изменениям прав;
- Хранение журналов не менее срока хранения ПДн.

### 12.4. Резервное копирование
- Полное резервное копирование БД + файлов (вложения) **ежедневно**;
- Инкрементальные копии чаще;
- Хранение копий по схеме 3-2-1;
- Регулярная проверка восстанавливаемости (тестовый restore);
- RPO ≤ 24 ч, RTO ≤ 4 ч.

### 12.5. Доступность и надёжность
- Развёртывание на отказоустойчивой конфигурации (при необходимости);
- Мониторинг доступности и алерты.

## 13. Уведомления

### 13.1. Каналы
- **Email** — основной канал, обязателен;
- **Push (PWA)** — для пользователей, установивших приложение/подписавшихся.

### 13.2. События для уведомлений
- Назначение новой оценки (как оценщику и как оцениваемому);
- Напоминания о дедлайне оценки;
- Эскалация просрочек (сотруднику → руководителю → HR);
- Назначение курса / приближение дедлайна обучения;
- Результат проверки практического задания;
- Получение благодарности / запрос обратной связи;
- Публикация нового ИПР / изменение статуса пунктов ИПР;
- Формирование итогового отчёта по циклу.

### 13.3. Настройки
- Пользователь может выбрать каналы (email/push) и типы уведомлений (в рамках допустимого);
- HR может рассылать **ручные уведомления** выбранной аудитории.

## 14. Пользовательские интерфейсы (ключевые экраны)

### 14.1. Общие
- **Вход/SSO** — единая страница логина;
- **Главный дашборд** — вид зависит от роли;
- **Профиль сотрудника** — контакты, фото, роль, подразделение;
- **Центр уведомлений** — колокольчик в шапке;
- **Настройки** — профиль, каналы уведомлений, подписка на push.

### 14.2. Модуль оценки
- Список циклов оценки (HR/руководитель);
- Мастер создания цикла (шаги: шаблон → участники → сроки);
- Форма заполнения оценки (оценщика): компетенции + комментарии;
- Просмотр результатов (агрегированных, с учётом анонимности).

### 14.3. Модуль обучения
- Каталог курсов (плитки/список, фильтры);
- Страница курса (описание, программа, запись);
- Проходжение урока / теста / задания;
- Личный кабинет обучения (мои курсы, прогресс);
- Редактор курса (Методолог): структура, загрузка материалов, настройки теста.

### 14.4. Модуль ИПР
- Просмотр и редактирование плана;
- Визуализация прогресса;
- Отметки о завершении пунктов.

### 14.5. Аналитика
- Дашборды (см. §9) с фильтрами по периоду/подразделению;
- Экспорт отчётов.

### 14.6. Обратная связь и портфолио
- Подача благодарности / запрос ОС;
- Лента портфолио сотрудника.

## 16. Рекомендуемый план разработки (по фазам)

Хотя сроки не ограничены, для управляемости предлагается поэтапная поставка.

### Фаза 1. Фундамент и оценка (MVP)
- Развёртывание on-premise, авторизация (SSO + пароль);
- Интеграция с 1С:ЗУП (оргструктура);
- Конструктор компетенций + шаблоны;
- Циклы оценки 360° + самооценка;
- Полная анонимность и агрегация;
- Базовые отчёты и дашборд по сотруднику;
- Уведомления (email + напоминания/эскалация).

### Фаза 2. Обучение и ИПР
- Встроенный LMS (тексты, тесты, задания с проверкой);
- Каталог курсов, авторский редактор;
- Формирование ИПР (авто + правка);
- Дашборды по подразделениям и обучению;
- Push-уведомления (PWA).

### Фаза 3. Аналитика, обратная связь и портфолио
- Непрерывная обратная связь и благодарности;
- Журнал достижений (портфолио);
- Расширенная аналитика и экспорт;
- Оптимизация производительности;
- Тюнинг безопасности и журналирования.

### Фаза 4. Развитие
- **Целеполагание MBO/OKR** (issue #37 — подтверждено заказчиком как метод оценки):
  - Модели целей (Objective) и ключевых результатов (Key Results);
  - Привязка к циклам оценки и к ИПР (завершённые/просроченные цели влияют на оценку);
  - Отображение прогресса по KR в дашбордах сотрудника и подразделения;
  - Календарный и финансовый периоды (квартал/год — настраивается).
- **Цифровые сертификаты (PDF)** (issue #38) — по приоритету заказчика: генерация PDF в фирменном стиле по завершении курса, запись в портфолио.
- ~~Мультиязычность~~ — **отклонено** заказчиком (только русский).
- ~~Нативное мобильное приложение~~ — **отклонено** заказчиком (PWA покрывает мобильные сценарии).

## 18. Глоссарий

- **360°** — метод оценки, при которой сотрудника оценивают со всех сторон (руководитель, коллеги, подчинённые, иногда клиенты) + самооценка.
- **ИПР** — индивидуальный план развития сотрудника.
- **LMS** (Learning Management System) — система управления обучением.
- **RBAC** (Role-Based Access Control) — управление доступом на основе ролей.
- **MBO / OKR** — методы целеполагания (Management by Objectives / Objectives and Key Results).
- **Грейд** — уровень должности/квалификации сотрудника.
- **PWA** (Progressive Web App) — веб-приложение с возможностями мобильного (push, офлайн, установка).
- **SSO** (Single Sign-On) — единый вход через корпоративную учётную запись.
- **152-ФЗ** — Федеральный закон РФ «О персональных данных».
- **УЗ** (уровень защищённости) — категория ИСПДн по 152-ФЗ.
